블록체인 연동은 한 번 배포한 컨트랙트와 한 번 보낸 트랜잭션을 되돌리기 어렵다는 점에서 일반 API 연동과 다릅니다. 개발에 들어가기 전에 아래를 먼저 정합니다.

## 지갑과 권한
- 회사 자산을 다루는 지갑은 누가, 몇 명의 승인으로 움직일 수 있는가 (멀티시그)
- 개인키·시드는 어디에 보관하고, 담당자가 바뀌면 어떻게 넘기는가
- 운영용 핫월렛과 보관용 콜드월렛의 한도를 어떻게 나누는가

## API·웹훅 통합
- 온체인 이벤트(입금, 전송, 컨트랙트 호출)를 어떤 방식으로 받아 기존 시스템에 반영할지
- 블록 재구성(reorg)에 대비해 몇 블록 확인 후 확정으로 볼지
- 외부 노드·인덱서 장애 시 대체 경로

## 보안·운영 모니터링
- 컨트랙트 배포 전 감리(오딧) 범위와 일정
- 이상 거래 알림 기준과 받는 사람
- 관리자 권한 사용 기록(감사 로그)

> 체크리스트의 절반 이상은 기술이 아니라 운영 규칙입니다. 그래서 개발 전에 정해야 합니다.
